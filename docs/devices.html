Every Magic device is a different Windows problem

Apple’s Windows story stopped at Boot Camp. Later PIDs are different HID layouts, power sources, and missing INF lines. We built a tray that tells the truth per PID — not one kernel driver for the whole line, and not a paid clone of Magic Utilities.

Why we went this way

  • v1/v2 already have a signed Boot Camp package. Replacing it with self-signed KMDF would force Test Mode on people who do not need it.
  • v3 is a new PID and a different collection layout. Forcing applewirelessmouse onto 0323 is the patched-Apple path: scroll vs battery, still unsigned. KMDF is the rewrite we could own. Research: Why v3 is hard.
  • Keyboards are not missing a mouse filter. The descriptor is Input-only; Windows cannot poll battery until an SDP registry patch. That is not a .sys.
  • Trackpad gestures are a product. MU sells that. We ship battery rows only so we do not pretend we cloned it.

In vs out vs MU: DESIGN-mu-free-parity.md. If you need WHQL + Secure Boot on a 2024 mouse today, MU is still the commercial signed-driver answer. If you need battery + mouse scroll without a subscription, this is what we could ship honestly — and stars plus an EV cert are how the v3 filter becomes a normal Windows driver.
