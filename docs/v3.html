Why the Magic Mouse v3 (2024, USB-C) won’t scroll on Windows 10 and Windows 11

  • Magic Mouse v3 is our shorthand for Apple’s 2024 model with the USB-C port. Apple just calls it Magic Mouse, so we add the year and the port.
  • Windows 10 and Windows 11 know that mouse by the hardware code 0323.
  • Magic Mouse v2 (Lightning), from 2015, is code 0269. Magic Mouse v1 (AA batteries), from 2009, is 030D.
  • All three look alike. To Windows they are three different products.
  • Apple never wrote a Windows driver for the USB-C one, so "install the Apple mouse driver" is bad advice for it.

Why did Apple’s 2024 Magic Mouse stop scrolling on Windows 10 and Windows 11?

Apple released a new Magic Mouse in 2024 that charges through USB-C. Windows gives every model a four-character hardware code, and this one is 0323. Apple’s Boot Camp Windows driver only lists the older codes. So Windows moves your pointer, but nothing tells it that a swipe across the mouse means scroll.

  • You didn’t break your mouse. Nobody wrote a Windows driver for your exact model.
  • Clicking and moving still work. Finger scrolling and the battery percent are what you lose.
  • A small extra Windows driver puts scrolling back on the Magic Mouse v3. We wrote one and it’s free.
  • PID is the name of that four-character code. It’s how Windows tells one model from another.
  • Boot Camp is Apple’s Windows support pack for Macs. Its mouse driver is where the old codes are listed.
  • Microsoft hasn’t signed our driver yet, so Windows only loads it in Test Mode. Test Mode is a setting that tells Windows to accept a driver Microsoft hasn’t stamped. Signing costs money, and that’s what we’re saving for.

The rest of this page is the detail behind that summary. You don’t need it to get scrolling back — the driver page has the steps for each model.

Do Magic Mouse v1 (AA batteries) and v2 (Lightning) already work on Windows 10/11?

Yes. Both older mice scroll with a Windows driver Apple shipped years ago inside Boot Camp. That driver lists the codes 030D and 0269, and Microsoft already signed it. Install it and finger scrolling works on Windows 10/11 with no extra settings and no Test Mode.

  • Magic Mouse v1 has a door for two AA batteries. Magic Mouse v2 charges through Lightning. Apple’s file lists both.
  • The Apple Wireless Mouse (AA batteries), code 0310, rides on the same file.
  • We point at the copy hosted by tealtadpole.
  • Because that file is signed, Windows loads it normally. Nothing about your PC has to change.
  • This Boot Camp path is for mice only. Keyboards and trackpads don’t get a scrolling driver from us.

Why does scrolling die after the Magic Mouse v3 goes to sleep?

Think of the mouse as a house with two rooms. One room reports movement and finger scrolling. The other reports the battery percent. When the Bluetooth link goes idle, Windows can remember the house as one room. Your pointer keeps working, scrolling is gone, and rebooting doesn’t rebuild the wall.

  • Room 1 is the pointer and finger scrolling.
  • Room 2 is the battery percent that Magic Tray shows next to your clock.
  • Windows caches the layout it saw last, so a restart just reloads the broken version.
  • Unpairing the mouse and pairing it again can rebuild the wall. A filter driver stops it collapsing in the first place.

The kernel repo calls the two states Mode A and Mode B. Same idea, without the HID names. HID is the standard language mice and keyboards use to describe themselves to a computer.

How does a Windows filter driver put finger scrolling back?

Windows never turns a swipe on the mouse surface into wheel scrolling by itself. Something has to sit between Bluetooth and Windows, read where your fingers are, and hand Windows ordinary scroll wheel events. A Windows driver in that slot is called a lower filter. It doesn’t replace the Windows mouse driver; it feeds it.

  • LowerFilter is the Windows name for a driver that slots in underneath the main one.
  • It reads what the mouse actually sent, edits it, then passes it up the stack.
  • Apple’s Boot Camp driver uses this same slot for Magic Mouse v1 and v2. Our driver uses it for the v3.

KMDF is the kind of Windows driver that loads deep in the system, written with Microsoft’s own framework for drivers. It’s the same slot Apple’s old file used, so nothing exotic is going on. What’s new is the mouse it targets: PID 0323, which Boot Camp has no entry for.

Cursor and finger scrolling live here. Windows holds this half open, so OPEN_FAILED err=5 in the tray log is normal, not a fault.

COL02 · Input 0x90

The battery half

The battery percent arrives here, in byte 2 of report 0x90. It isn’t in feature report 0x47, the kind a device only answers when asked. It isn’t in the iPhone Hands-Free or WMI data other tools read either.

Every route trades something away today. A patched Apple driver can hold scrolling but lose the battery percent. The stock setup can keep the battery percent but lose scrolling. Our KMDF driver aims at both, and it’s still self-signed — that’s what the funding goal is for.

Why is there a tray app as well as a Windows driver?

A Windows driver makes hardware work. It doesn’t draw anything on your screen. Magic Tray is the small app beside your clock that shows the battery percent for your mouse, keyboard or trackpad. The driver and the app do different jobs, and you can use either one on its own.

  • A driver can’t put "28%" next to your clock. Only an app can do that.
  • A driver doesn’t know your keyboard’s Bluetooth address. The app looks it up.
  • The tray shows battery for mice, keyboards and trackpads. The scrolling driver is for Magic Mouse only. See Devices.

Common questions about the Magic Mouse v3 on Windows 10/11

Is the Magic Mouse v3 (2024, USB-C) the same as Magic Mouse v2 on Windows?

No. Magic Mouse v2 charges through a Lightning port, and Windows knows it by the code 0269. The Magic Mouse v3, Apple’s 2024 model, charges through a USB-C port, and Windows knows it as 0323. Apple’s Boot Camp Windows driver lists 0269 and never listed 0323, so it will not load on the newer mouse.

Why does Magic Mouse v3 scrolling stop working on Windows 10/11 after the mouse sleeps?

Your mouse reports itself to Windows in two separate parts: one for movement, one for battery. After the Bluetooth link goes idle, Windows can cache the two parts as one. The pointer survives because it is in the part that is left, and finger scrolling does not. Restarting Windows does not bring it back.

Can I install Apple’s Boot Camp Windows driver on the Magic Mouse v3 (2024, USB-C)?

No. A Windows driver only loads for the hardware codes written inside its setup file, and Apple’s file does not contain 0323. Windows will refuse it, or it will load and still leave you without finger scrolling. That is why the 2024 USB-C mouse needs a Windows driver of its own.
